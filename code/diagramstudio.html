Design Grammar & Specification Handbook

This framework defines a systematic visual language for cloud, security, and AI system diagrams. Follow this specification to create diagrams that look polished, clear, and uniform across documentation, decks, and whitepapers.

1. Blueprint Grid

A $20 \times 20\text{px}$ graph-paper grid pattern (`#E6E5DE`) dashed at `2.5 2.5` on a soft warm white canvas (`#FAFAF8`).

2. Grouped Boundaries

Logical boundaries (e.g., Authorization Server, MCP Server) use lightly tinted background fills (`#F8F7FF`, `#EEF2FF`) with nested pure-white cards.

3. Orthogonal Connectors

Flow paths follow strict 90-degree orthogonal routes with clean dashed strokes (`#9CA3AF`, `3.5 3.5`) and centered pill badges.

Complete TypeScript Interface & Schema

You can copy and save this schema into any project to generate SVGs programmatically via JavaScript, Python, or CLI tools.

interface DiagramConfig {
  meta: {
    title: string;
    description: string;
    viewBox: { width: number; height: number };
    grid?: { size: number; color: string; dash: string; opacity: number };
  };
  nodes: DiagramNode[];
  connectors: DiagramConnector[];
  footer?: {
    text: string;
    tags?: string[];
  };
}

type DiagramNode = CardNode | GroupNode;

interface CardNode {
  id: string;
  type?: "card";
  x: number;
  y: number;
  width: number;
  height: number;
  rx?: number; // default: 16
  fill?: string; // default: "#FFFFFF"
  stroke?: string; // default: "#E2E2DC"
  strokeWidth?: number;
  
  // Header / Category Eyebrow
  category?: {
    text: string;
    color?: string; // e.g. "#635BFF", "#0066FF"
    size?: number; // default: 10
    weight?: number; // default: 700
  };

  // Main Heading Title
  title?: {
    text: string;
    color?: string; // default: "#111827"
    size?: number; // default: 14 to 18
    weight?: number;
    align?: "left" | "center";
  };

  // Subtitle / Descriptor
  subtitle?: {
    text: string;
    color?: string;
    size?: number;
  };

  // Optional Logo Embed
  logo?: {
    type: "image" | "svg-path";
    url?: string; // for image
    path?: string; // for raw svg path string
    viewBox?: string; // e.g. "0 0 453.3 73.9"
    fill?: string;
    x: number;
    y: number;
    width: number;
    height: number;
  };

  // Optional Client Icon Chips (as used in MCP Client)
  chips?: Array<{
    title: string;
    iconUrl: string;
    x: number;
    y: number;
    width?: number; // default: 30
    height?: number; // default: 30
  }>;
}

interface GroupNode {
  id: string;
  type: "group";
  x: number;
  y: number;
  width: number;
  height: number;
  rx?: number; // default: 18
  fill: string; // e.g. "#F8F7FF" or "#EEF2FF"
  stroke?: string;
  header: {
    text: string;
    color: string;
    size?: number;
  };
  children: CardNode[];
}

interface DiagramConnector {
  id: string;
  path: string; // SVG path string e.g. "M 190 72 L 318 72"
  stroke?: string; // default: "#9CA3AF"
  strokeWidth?: number; // default: 1.3
  dash?: string; // default: "3.5 3.5"
  animated?: boolean;
  markerEnd?: string; // default: "url(#arrow)"
  badge?: {
    x: number;
    y: number;
    width?: number;
    height?: number;
    bg?: string; // default: matches canvas "#FAFAF8"
    lines: Array<{
      text: string;
      color?: string;
      size?: number;
      weight?: number;
    }>;
  };
}

How to Route Connectors & Place Badges

Connectors use standard SVG path `d` strings. To maintain the crisp architectural look, avoid arbitrary diagonals. Always use straight lines or right-angle orthogonal turns.

1. Horizontal Straight Path

"M {x1} {y} L {x2} {y}"

Badge position: $$x = \frac{x1 + x2}{2}, \quad y = y$$

2. Right-Angle Turn (L-shape)

"M {x1} {y1} L {x2} {y1} L {x2} {y2}"

Moves horizontally from $(x1, y1)$ to corner $(x2, y1)$, then vertically down to target $(x2, y2)$.
